# Buff watch face: notes for Claude Code

A Garmin Connect IQ watch face, written in Monkey C, for 454×454 AMOLED watches with the on-watch editor (tested on the
fēnix 8 47/51 mm). A buddy in the middle gets stronger as the right arc's metric approaches its goal. README.md is
the user guide; this file is for working on the code.

## Commands

| | |
|---|---|
| `make sim` | start the Connect IQ simulator (leave it open) |
| `make mockup` | build with the fixed values in `Mock` (`source/BuffData.mc`), clock frozen at 14:32, and load it into the simulator. **The way to check visual changes.** |
| `make run` | the real build in the simulator (live data from the simulator's own sensors) |
| `make test` | unit tests (`source/test/Tests.mc`) in the simulator; must print `PASSED` |
| `make build` | release build `bin/Buff.prg` for `DEVICE` (default `fenix847mm`) |
| `make release` | release builds for every watch in `manifest.xml` |
| `make assets` | rebuild `resources/gen`, `resources/fonts` and `source/gen/BuffGen.mc` from `design/` and `tools/build_assets.py` (needs Python 3, Pillow with raqm, numpy, `rsvg-convert`) |
| `make sideload` | macOS: build and copy to a watch over USB (`brew install libmtp`). Start it *before* the watch is plugged in. |

To see a change in the simulator: edit, `make mockup`, then save a screenshot (simulator menu: File > Save Screen
Capture). To try other values, edit the `Mock` constants: which metric each arc shows (`LEFT`, `RIGHT`), their
readings, the theme, the streak, and deficit mode. To try the on-watch editor, run `make run`, then File > Edit Watch Face.

## Map

| File | What |
|---|---|
| `source/BuffApp.mc` | app entry; the background fetch (deficit mode only); editor mode |
| `source/BuffView.mc` | all drawing: face layer, buddy, time, always-on; reading Customize (`applyConfig`); the editor's slot highlight |
| `source/BuffData.mc` | what the face shows, refreshed once a minute; `Slots` (what each arc tracks); `Mock` values |
| `source/Metrics.mc` | each metric: where its value comes from, its goal or scale, label, icon; active calories (BMR) |
| `source/Buff.mc` | pure maths: levels, deficit, streak. Unit-tested. |
| `source/Config.mc` | build-time options: calorie goals, scales, deficit target |
| `source/BuffDraw.mc` | layout constants, colours, `Theme`, arc and text helpers |
| `source/Secrets.mc` | deficit-mode server URL and token: empty in the repo, **never commit real values** |
| `source/gen/BuffGen.mc` | GENERATED by `tools/build_assets.py`: layout numbers, theme tables, resource tables. Don't hand-edit; change the script and run `make assets`. |
| `resources/configs/watchface.xml` | the on-watch editor: Style (colour) and the two data slots |
| `resources/gen`, `resources/fonts` | GENERATED images and bitmap fonts (committed, so building needs no Python) |
| `design/muscle.html` | the buddy's design (SVG template + the JS that poses it); `build_assets.py` renders it |
| `tools/` | `build_assets.py` (asset pipeline), `render.py`, `bmfont.py`, `sideload.sh`, fonts |
| `extras/intake-server/` | optional server for deficit mode |

## How it works (keep these rules)

- **Speed on the watch.** The watch is roughly 10× slower than the simulator. Everything except the buddy is drawn into
  one off-screen bitmap once a minute (and on wake), then copied to the screen every second, with the buddy's
  animation frame drawn on top. Never draw one off-screen bitmap into another; don't add per-second work.
- **The buddy is pre-rendered.** Every theme × state × frame is a PNG from `build_assets.py`. The fill is a "dry" image
  plus a "wet" image clipped below the fill line. To change how he looks, change `design/muscle.html` or the palette
  code in `build_assets.py`, then run `make assets`.
- **Text uses bitmap fonts** (Barlow Condensed) with letter-spacing baked in. A new character in a label needs adding
  to that font's character list in `TEXT_FONTS` (`build_assets.py`).
- **Always-on** (wrist down) must stay under about 10% of the screen's light, with no animation, and shifts by up to
  2 px each minute (AMOLED burn-in).
- **The on-watch editor only offers Garmin's complication types.** A new metric needs a type from that list
  (`Complications.COMPLICATION_TYPE_*`), a case in `Metrics.fromType`, `Metrics.live`, a label and an icon, and a
  `<type>` line in `watchface.xml` for both slots. HRV isn't available to watch faces.
- **Levels** are fractions of the goal (`Buff.state`): Flatlining under 1/6, Active from 1/6, Intense from 2/3, Insane
  at 1. For lower-is-better readings (stress, resting HR, recovery), the buddy's progress is flipped (`Reading.good`).
- **Permissions:** `ComplicationSubscriber` (reading metrics), `UserProfile` (active calories, resting HR),
  `Background` and `Communications` (deficit mode only).

## Before you finish a change

1. `make test` passes.
2. `make mockup` and look at a screenshot, including the states and themes your change touches.
3. If you changed the layout or anything drawn, check always-on too (simulator: Settings > Display Mode > Always-On).
4. Never commit a developer key (`*.der`, `*.pem`) or real values in `source/Secrets.mc`.
